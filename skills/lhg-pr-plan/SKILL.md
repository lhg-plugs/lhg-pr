# lhg-pr-plan：发布节奏规划

目标：发稿不是"发出去了事"，而是"发出去、被看见、能量化"。核心纪律：**先定目标再排时间，复盘指标发稿前就定好**。

## 1. 何时使用

- 通稿和媒体清单都有了 → 全流程（定目标→排时间轴→定复盘指标）
- 用户问"什么时候发最好"→ 单讲第 3 步
- 发稿后问"效果怎么样"→ 单讲第 5 步复盘

## 2. 第一步：定发稿目标（三选一）

| 目标 | 适用场景 | 媒体策略 | 成功标准 |
|---|---|---|---|
| 曝光量 | 新品发布、品牌声量 | 扩散媒体为主，量大 | 转载量、阅读量 |
| 行业背书 | 融资、ToB 获客 | 核心媒体为主，质重 | 核心媒体报道数、引用率 |
| 危机/声明 | 澄清、回应 | 核心+官方渠道同步 | 核心媒体首发、舆情转向 |

**一句话**：目标不同，媒体清单、发布时间、复盘指标全都不同；目标没定就别排时间表。

## 3. 第二步：排时间轴

### 标准时间轴（新品发布类）

| 节点 | 时间 | 事项 | 负责人占位 |
|---|---|---|---|
| T-7 | 前一周 | 通稿初稿完成，内部终审 | 待补充 |
| T-3 | 前三天 | 核心媒体一对一建联，发 embargo 稿 | 待补充 |
| T-1 | 前一天 | 通稿定稿、配图与联系人确认；确认记者收到稿 | 待补充 |
| T0 | 发布日 | 统一发布时间点（建议上午 10 点）；自有渠道同步 | 待补充 |
| T+1 | 次日 | 监测首轮转载；未发布媒体跟进一次 | 待补充 |
| T+3 | 三天后 | 补发遗漏媒体；KOL 二次传播 | 待补充 |
| T+7 | 一周后 | 转载复盘 | 待补充 |

### 发布时间选择

- **工作日上午 10 点**是默认最优：记者刚开工，版面还没定。
- 避开周五下午（周末没人看）、重大公共事件当天（版面被占）。
- ToB 行业避开春节/国庆前后（一周没人审稿）。
- embargo 稿发布时间精确到小时，群发稿精确到"上午"即可。

## 4. 第三步：发布当日 checklist

- [ ] 通稿最终版已锁定（文件名带"终稿"和日期）
- [ ] 三个版本（长稿/短讯/社媒）都已终审
- [ ] 配图已压缩（单张 <2MB，记者邮箱收得到）
- [ ] 联系人电话已拨测（占位符不许发出去）
- [ ] embargo 媒体已书面确认发布时间
- [ ] 自有渠道定时发布已设置
- [ ] 舆情监测关键词已配置（公司名+产品名+创始人名）

**发布当日纪律**：T0 当天不改稿——要改提前一天改；发布后发现错别字走"更正说明"，不许偷偷换稿。

## 5. 第四步：转载复盘（四指标）

| 指标 | 怎么算 | 及格线参考 |
|---|---|---|
| 转载量 | 全网转载篇数（去重） | 核心目标曝光：≥50；背书目标：不唯量 |
| 核心媒体覆盖 | 核心清单中实际发布家数/总数 | ≥60% |
| 标题保真率 | 未被改标题的转载/总转载 | ≥70%（标题被大改=标题不合格） |
| 舆情正负面 | 正面+中性占比 | ≥90%，负面逐条登记处理 |

**复盘输出**：一页纸复盘报告——目标回顾→四指标→问题（哪家没发、为什么）→下次改进。复盘报告存档，下次发稿前先看。

## 6. 常见翻车与预案

| 翻车 | 预案 |
|---|---|
| embargo 被提前泄露 | 立即解除 embargo，全部提前发 |
| 核心记者临时说版面不够 | 给短讯版+专访邀约，不硬塞长稿 |
| 通稿出现事实错误已发出 | 1 小时内发更正说明给所有已发媒体，不许静默换稿 |
| 竞品同一天开发布会 | 错峰 2 小时，或改打"独家深度"牌 |
| 配图太大记者收不到 | 提前压缩+网盘链接双保险 |

## 7. 危机公关发稿特别时间轴

常规时间轴太慢，危机/声明类用"小时级"时间轴：

| 节点 | 事项 |
|---|---|
| T+0h | 舆情确认：事实是什么、先内部统一口径，不许对外猜测 |
| T+1h | 声明初稿：结论先行，三段以内，法务过一遍 |
| T+2h | 核心媒体同步 + 官方渠道发布（官网/公众号/视频号三端齐发） |
| T+4h | 监测首轮转载与评论，登记负面 |
| T+24h | 复盘：回应是否覆盖核心质疑，是否需要第二轮声明 |

**危机三不许**：不许删帖（删帖=心虚实锤）、不许"正在调查"拖过 24 小时（没结论就说"X小时内给结论"）、不许高管个人账号先于官方发声。

## 8. 复盘报告模板（一页纸）

```
# XX事件发稿复盘（日期）

## 目标回顾
- 发稿目标：曝光量/行业背书/危机声明（三选一）
- 是否达成：是/否，一句话原因

## 四指标
- 转载量：X 篇（目标 Y）
- 核心媒体覆盖：X/Y 家（X%）
- 标题保真率：X%
- 舆情正负面：正面 X%，负面 X 条（逐条登记）

## 问题
- 哪家核心媒体没发，为什么
- 哪个环节超时/出错

## 下次改进
- 1.
- 2.
```

**存档纪律**：复盘报告存进固定文件夹，下次发稿前先看上一篇——同样的坑不许踩两次。

## 9. 一句话记忆卡

- 目标：三选一（曝光/背书/声明），目标没定别排时间
- 时间：T-7到T+7，默认周二至周四上午10点发
- 当天：T0不改稿，错别字走更正说明
- 复盘：四指标发稿前定好，一页纸存档
- 危机：小时级时间轴，不删帖、不拖过24小时

## 10. 反模式

- ❌ 没有目标就排时间——"发了再说"等于没发。
- ❌ T0 当天改稿——发布流程最怕临时变卦。
- ❌ 复盘只数转载量——标题保真率和核心覆盖比总量重要。
- ❌ 负面舆情装没看见——24 小时内必须登记+定回应口径。
- ❌ 每次发稿从零开始——复盘报告是资产，建个文件夹存起来。

## 11. 自检与反馈

**质检门**：
- [ ] 发稿目标三选一是否明确
- [ ] 时间轴是否覆盖 T-7 到 T+7，发布时间是否避开坏时点
- [ ] 发布当日 checklist 是否逐项可执行（无"大概""尽量"）
- [ ] 复盘四指标是否在发稿前就定好

**标准冒烟用例**：输入"下周三新品发布，目标行业背书"→ 时间轴倒排：T0=下周三，T-3=本周日（提醒周末建联记者可能不回，提前到周五），复盘指标以核心覆盖为主。

**一键反馈**：发现某类事件时间轴不适用，到本仓库提 issue（标题前缀 `[lhg-pr-plan]`），附事件类型与建议调整。
