# lhg-pr-news：新闻通稿写作五步法

目标：把一堆事件信息变成"媒体愿意直接用的通稿"。核心纪律：**倒金字塔——最重要的放最前，删掉最后一段稿子依然成立**。

## 1. 何时使用

- 用户说"帮我写篇新闻稿"→ 全流程（信息清单 + 长稿 + 短讯 + 社媒版）
- 用户已有初稿想优化 → 跑第 4 步（三版本改写）+ 转 pr-check 自查
- 用户问"通稿一般什么结构"→ 单讲第 3 步

## 2. 第一步：事件信息清单（先问全）

动笔前必须集齐，缺项就追问，不许脑补：

| 信息 | 说明 | 缺失处理 |
|---|---|---|
| 何时 | 发布时间/事件时间，精确到日 | 不知道写"待定"，不许编日期 |
| 何地 | 城市+场馆 | 线上活动写"线上" |
| 何人 | 公司全称、发言人姓名+职务 | 发言人没有原话就别写引言 |
| 何事 | 发布了什么/发生了什么，一句话 | 抓不住一句话就还没想清楚 |
| 为何 | 为什么做这件事（战略意图） | 没有就别硬编，写事实 |
| 如何 | 怎么实现的（技术/模式/合作） | 涉密可写"细节未披露" |
| 关键数据 | 用户数/降本比例/融资金额等 | 每个数字都要有来源口径 |
| 引言 | 说话人原话（录音/文字实录） | 无实录不许编"XX表示" |
| 配图 | 现场图/产品图/信息图 | 无图先写稿，标注"配图待补" |
| 联系人 | 媒体联络人姓名/电话/邮箱 | 不许编造，留"待补充" |

**追问话术**："引言部分有发言人原话吗？有录音或文字实录最好，没有的话这段我们先空着，不编。"

## 3. 第二步：倒金字塔结构

```
标题（发生了什么，一句话）
  ↓
导语（5W1H，≤150字，删掉导语全文不成立）
  ↓
正文（事实展开：数据→细节→背景，按重要性递减）
  ↓
引言（说话人+原话，注明出处；最多两段）
  ↓
结尾（下一步计划/活动信息/联系方式）
```

**检验标准**：从结尾往前删段落，删到只剩标题+导语，新闻依然完整——这就是倒金字塔写对了。

### 各段写作要点

**标题**：主谓宾齐全，≤30 字；数字前置（"降三成"比"显著降低"有力）；不许用极限词。

**导语**：第一句必须回答"谁在何时何地做了什么"。150 字上限是铁律——超了就把细节踢到正文。

**正文**：一段一个事实；数据第一次出现时给口径（"试点二十家企业"而不是"很多企业"）；背景资料放最后一段。

**引言**：格式固定——"XX（姓名+职务）表示："+"原话"。原话可以精简但不许改意思；没有实录就不写。

**结尾**：下一步（巡展/上线时间）+ 联系方式；不许在结尾突然冒出新事实。

## 4. 第三步：三版本输出

| 版本 | 篇幅 | 用途 | 写法 |
|---|---|---|---|
| 长稿版 | 800~1200 字 | 核心媒体、官网新闻中心 | 完整五段结构 |
| 短讯版 | ≤300 字 | 门户快讯、地方媒体 | 标题+导语+一句话引言 |
| 社交媒体版 | ≤140 字 | 公众号/视频号/微博 | 口语化，带话题标签建议 |

**三版一致性检查**：标题核心事实一致、数字一致、引言一致；不许长稿说"降三成"短讯变"降五成"。

## 5. 第四步：数字与事实核对

- 每个数字回查来源：试点数据注明"试点"，全量数据注明"全量"。
- 时间核对：导语日期=事件日期=标题日期，三处一致。
- 人名职务核对：发言人职务以官方口径为准，不许"创始人兼CEO"自己发挥。
- 不许出现"据悉""据了解"这类无源表述——要么写明来源，要么删掉。

## 6. 第五步：落盘与审计

- 三个版本分别存为 `通稿-长稿版.md` / `通稿-短讯版.md` / `通稿-社媒版.md`。
- 跑 `scripts/audit/pr_audit.py`，blocker 清零。
- 转 `pr-check` 做人工四重自查。

## 7. 实战案例 walkthrough

输入："10月11日蓝鲸科技在北京发布智能客服系统，试点二十家企业客服成本降三成，创始人张伟有原话。"

**导语**（108字）：10月11日，蓝鲸科技公司在北京举行新品发布会，正式推出新一代智能客服系统。该系统通过多轮对话与情绪识别技术实现工单自动流转，旨在帮助电商与金融企业降低三成客服人力成本。

**引言**：蓝鲸科技公司创始人张伟表示："我们的目标是让每一家企业都用得起智能客服。"

**结尾**：蓝鲸科技公司计划于下季度启动城市巡展，覆盖十个重点城市。

完整版见 `fixtures/draft-good/通稿.md`。

## 8. 不同事件类型的结构微调

倒金字塔是默认结构，但四类事件要微调：

| 事件类型 | 调整点 | 说明 |
|---|---|---|
| 新品发布 | 标准五段 | 引言放创始人/产品负责人 |
| 融资消息 | 导语前置金额+领投方 | 数字是最大新闻点，别藏在正文 |
| 战略合作 | 何人写两家公司全称 | 签约双方对等呈现，不许只写自家 |
| 获奖/榜单 | 导语前置奖项含金量 | 写清颁奖方+评选范围，"野鸡奖"不如不发 |
| 声明/澄清 | 开头直接给结论 | "针对XX传闻，我司声明如下"，不许绕三段 |

**通用原则**：结构为新闻点服务；新闻点是数字就把数字提前，是结论就把结论提前。

## 9. 一句话记忆卡

- 结构：倒金字塔，删结尾稿子依然成立
- 信息：十项清单问全，缺项标"待定"不许编
- 引言：无实录不写，不编"XX表示"
- 数字：首次出现给口径，三版本一致
- 红线：不编数据、不编引言、不用极限词
- 落盘：三版本分别存文件，审计 blocker 清零再转 pr-check

## 10. 反模式

- ❌ 编造引言——没有实录的"XX表示"是新闻造假，不是文笔。
- ❌ 导语写成抒情散文——导语只回答 5W1H，形容词全部踢到正文。
- ❌ 三个版本数字打架——发布前必须做一致性核对。
- ❌ 用"第一/唯一"撑场面——没有第三方数据来源的极限词一律删。
- ❌ 联系人电话现编——错一个数字，媒体就找不到你。

## 11. 自检与反馈

**质检门**：
- [ ] 事件信息清单十项是否集齐，缺项是否标注"待定/待补充"
- [ ] 导语是否 ≤150 字且 5W1H 齐全
- [ ] 每段引言是否有姓名+职务出处
- [ ] 三版本数字是否一致
- [ ] 是否出现极限词/编造数据（一出现即返工）

**标准冒烟用例**：输入含"发布时间待定、无引言实录"的事件 → 导语日期写"待定"，不写引言段，输出明确标注两处待补充。

**一键反馈**：发现结构不适用某类事件（如讣告/声明类），到本仓库提 issue（标题前缀 `[lhg-pr-news]`），附事件类型与卡点。
